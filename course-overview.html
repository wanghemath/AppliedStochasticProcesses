Applied Stochastic Processes: Modeling, Simulation, and AI

For MS Applied Mathematics and MS Statistics students. Prerequisites: basic probability, statistics, and programming. This course is independent of MATH 6241; neither course requires the other.

What you will learn to do

Start with a real question, construct a model, and use computation to find out where the model helps and where it fails. Definitions, formulas, and assumptions stay visible; assessment emphasizes computational evidence and explanation rather than theorem proofs.

  • Translate an operational or scientific question into a stochastic model with explicit states, time scale, units, and assumptions.
  • Estimate parameters from observations, implement simulations, and verify their behavior against analytical checks.
  • Validate predictions on held-out observations, quantify uncertainty, and compare practical scenarios.
  • Communicate a reproducible analysis and defend every model, code choice, and consequential use of AI assistance.
One sustained project, six small labs.

Survey the major process families through compact experiments. Develop only two or three complementary methods in your project, including a simple baseline and at least one stochastic model. You are not expected to fit every model taught in the course.

A workable weekly rhythm

Plan for approximately 100 minutes of class and 3–4 hours outside class each week, including project work. A typical class uses 20 minutes for concepts, 25 for a worked example, 30 for a guided experiment, and 25 for interpretation and project discussion. Short starter notebooks keep setup and boilerplate out of the workload. Each of the first twelve modules has a 40–55 minute guided notebook that fits within the worked-example and experiment blocks; its 25–35 minutes of student exercises count toward ordinary outside-class practice. Module 13 uses 40–50 minutes of guided audit work and 20–30 minutes of refinement within the existing project allocation. Module 14 uses 30–40 minutes of guided synthesis and 20–30 minutes of rehearsal within the existing project allocation, followed by the scheduled six-minute presentation and questions.

Outside class, budget 30–45 minutes for preparation, 45–75 minutes for notebook practice, and 90–120 minutes for your project. In submission weeks, a 60–90 minute concept lab replaces ordinary notebook practice. Proposal and checkpoint submissions reuse project work already completed. Week 13 uses the existing project allocation for refinement, reproducibility, and AI-output verification; week 14 reserves it for presentations and individual explanations.

Each module follows the same sequence: practical question → concepts and mathematics → worked computation → interactive experiment → real data → validation → interpretation → exercises → optional extension. Predict a result before changing a control; then explain the difference between the prediction and the evidence.

Core software is Python with NumPy, pandas, SciPy, and Matplotlib. Browser lessons run without a Python server. All 14 notebooks use the same bundled data and require no paid services or API keys. No additional specialized modeling package is required; optional extensions never increase the required workload.

Set up once, then run locally

Keep the complete course folder together, including assets/, data/, modules/, and notebooks/. Open index.html directly in your browser to read the lessons and use the simulations. The HTML does not need a Python server or an internet connection.

For notebook computation, use an installed Python 3 and open a terminal in the course’s top-level folder, where requirements.txt is located. Create an isolated environment:

python -m venv .venv

Activate it on macOS or Linux:

source .venv/bin/activate

On Windows PowerShell, use this activation command instead:

.\.venv\Scripts\Activate.ps1

Install the course dependencies and start JupyterLab. The first installation requires an internet connection; the supplied data and notebooks can then run locally.

python -m pip install -r requirements.txt
jupyter lab

In JupyterLab, open notebooks/module01_stochastic_models.ipynb, notebooks/module02_markov_chains.ipynb, notebooks/module03_stationarity_hitting.ipynb, notebooks/module04_monte_carlo.ipynb, notebooks/module05_mcmc.ipynb, notebooks/module06_branching.ipynb, notebooks/module07_poisson.ipynb, notebooks/module08_renewal_ctmc.ipynb, notebooks/module09_queueing.ipynb, notebooks/module10_brownian_dynamics.ipynb, notebooks/module11_gaussian_processes.ipynb, notebooks/module12_validation_sensitivity.ipynb, notebooks/module13_reproducibility_verification.ipynb, or notebooks/module14_presentations_explanations.ipynb, choose the Python kernel from this environment, and select Kernel → Restart Kernel and Run All Cells. Read the explanations and outputs from top to bottom before completing the exercises. Keep the notebook beside its course folders so the relative data paths work; do not download only the notebook into a different directory.

NumPy and pandas handle arrays and tables; SciPy supplies probability calculations; Matplotlib draws the figures. JupyterLab opens the notebook. No API key, paid account, or AI service is needed. Run the notebook again after edits to confirm that the result does not depend on hidden kernel state.

The full 14-week outline

All 14 modules have complete lesson and notebook pairs. The final two modules refine and communicate the same sustained project. Mathematical expressions preview the essential ideas and are developed with examples in their respective modules.

1 · Stochastic models
Ready		What does a probability say about tomorrow's demand? A process is $\{X_t:t\in T\}$; a sample path fixes an outcome. For a binary indicator $Y_t\sim\mathrm{Bernoulli}(p)$, $E[Y_t]=p$. Review conditional probability, expectation, and variability.Simulate independent binary paths, compare Monte Carlo averages with their analytical benchmark, and audit a flawed function that repeats one random draw. Fit a high-demand baseline to real bike counts and test a later period.Define a measurable outcome and distinguish observed data, fitted models, and unmeasured scenario assumptions. Module 1 notebook.
2 · Markov chains
Ready		Does today's state help predict tomorrow? $P_{ij}=P(Y_{t+1}=j\mid Y_t=i)$, $\sum_jP_{ij}=1$, and a row distribution advances as $\nu_{t+k}=\nu_tP^k$ for a time-homogeneous chain.Estimate transitions from consecutive observations and compare one-step and multistep forecasts with simulated frequencies. Investigate sparse rows and a changing transition law.Choose defensible states; compare a chain with the Module 1 baseline. Module 2 notebook. Lab 1 due.
3 · Stationarity, absorption & hitting times
Ready		What fraction of time is a system in a state, how long until a target is first reached, and which absorbing outcome occurs? $\pi P=\pi$, $\sum_i\pi_i=1$, $\pi_i\geq0$, and $\tau_A=\inf\{t\geq0:Y_t\in A\}$. Stationarity means invariance. A finite irreducible chain has a unique stationary distribution and convergent time averages; aperiodicity additionally gives convergence of state distributions from every initial distribution.Compare simulated occupation proportions and hitting times with linear-system calculations, and compute absorption probabilities. Use a periodic counterexample; compare the fitted bike chain’s stationary and finite-window summaries with later observations without treating a high-demand day as permanent absorption.Choose an optional long-run fraction or first-hit-within-window metric for the existing project and check its assumptions. Module 3 notebook. Begin Lab 2 Part A; submit the combined lab in week 4.
4 · Simulation accuracy & variance reduction
Ready		Is a simulation estimate precise enough? $\hat\mu=N^{-1}\sum_{r=1}^NZ_r$ has estimated standard error $s_Z/\sqrt N$ for independent replications with finite variance. Paired scenario differences require a paired standard error. Importance sampling uses $g(Y)f(Y)/q(Y)$ with $q$ positive wherever $g(y)f(y)\ne0$.Compare repeated estimates and interval coverage; distinguish independent paths from dependent days. Use common random numbers for a scenario difference and a weighted rare-event estimate with an exact benchmark. Expose zero-event false precision and unstable importance weights.Set a conditional simulation precision target. Module 4 notebook. Complete Lab 2 Part B and submit one combined lab with Module 3 Part A. The concise proposal/data audit reuses existing work.
5 · MCMC and Bayesian calibration
Ready		How uncertain are fitted transition probabilities? A Metropolis–Hastings move uses $\alpha=\min\{1,\pi(\theta')q(\theta\mid\theta')/[\pi(\theta)q(\theta'\mid\theta)]\}$ for target density $\pi$. Independent Beta priors give an exact posterior benchmark for the bike chain’s two transition hazards.Compare a supplied sampler with the conjugate result. Change proposal scale and inspect multiple-chain traces, autocorrelation, basic split $\widehat R$, and mean MCSE. These teaching diagnostics can reveal failures; they do not prove convergence. Keep posterior uncertainty separate from computational error and model assumptions.Module 5 notebook. Begin Lab 3 Part A; Part B follows in Module 6, with one combined submission in week 6. Propagate parameter uncertainty when useful; exact posterior sampling is available here, and MCMC is optional for the sustained project.
6 · Branching processes
Ready		Can growth still end in extinction? $Z_{n+1}=\sum_{i=1}^{Z_n}\xi_{n,i}$ with independent, identically distributed offspring. With mean offspring $m$, $E[Z_n\mid Z_0]=Z_0m^n$; eventual extinction from one ancestor is the smallest solution of $q=G(q)$ in $[0,1]$. The deterministic one-child law is the critical exception.Compare means, typical paths, and finite-horizon extinction for Poisson offspring. Separate eventual extinction from “zero by generation 20.” Use a clearly synthetic offspring sample to propagate a Gamma–Poisson posterior for $m$; a bike-count conditional-model audit shows why daily rentals do not identify actual offspring or generations.Module 6 notebook. Use branching only when generations and offspring can be justified. Complete Lab 3 Part B, and submit once with Module 5 Part A in week 6; no additional project is added.
7 · Poisson processes
Ready		When is a constant event rate credible? For a homogeneous process, $N(t+h)-N(t)\sim\mathrm{Poisson}(\lambda h)$ with independent increments and exponential interarrival times. With deterministic time-varying rate, the mean increment is $\int_t^{t+h}\lambda(s)\,ds$.Verify count moments and waiting times; compare synthetic rate profiles with equal integrated intensity but different event timing. Fit constant and working-day calendar rates using January–August bike counts, then assess September–December counts and persistence on the same dates. Daily totals do not identify exact event times or intraday peaks.Module 7 notebook. Begin Lab 4 Part A; Module 8 completes Part B, with one combined submission in week 8. Separate observed daily intensity from assumed within-day timing, and treat dispersion and temporal residuals as model criticism.
8 · Renewal, continuous-time & birth–death models
Ready		How does elapsed waiting time change the next wait? A renewal count is $N(t)=\max\{n:W_1+\cdots+W_n\leq t\}$ for iid positive gaps. A continuous-time chain has generator $Q$ with nonnegative off-diagonal rates and zero row sums; its transition matrix is $P(t)=e^{Qt}$. Birth–death chains allow adjacent-state jumps.Compare equal-mean exponential and nonexponential renewal gaps and conditional residual waits. Verify exact holding-time simulation and stationary time occupation for a synthetic finite bike-station model, then expose the bias in counting jump visits. Audit observed daily bike-count exposures and the absence of station inventory and event timestamps; these totals cannot calibrate station holding times.Module 8 notebook. Justify timing and state observations, account for censoring, and keep assumed station rates separate from fitted daily summaries. Complete Lab 4 Part B; submit once with Module 7 Part A in week 8. No additional project is added.
9 · Queueing systems & event simulation
Ready		How much capacity prevents long waits? For a stable M/M/1 queue, $\rho=\lambda/\mu<1$ and $E[W]=1/(\mu-\lambda)$ for total time in system. Distinguish waiting time from service time and state the arrival, service, server, and stability assumptions.Implement a next-event calendar and verify it against a hand trace and Lindley’s recursion. Compare M/M/1 and M/D/1 benchmarks after a stated warm-up, use independent replication means for Monte Carlo error, and stress bursty arrivals and overload. Verify finite-path area identities before interpreting a steady-state result.Module 9 notebook. Begin Lab 5 Part A; Module 10 completes Part B, with one combined submission in week 10. Compare two assumed service-capacity scenarios anchored to earlier bike-rental volume, while identifying absent queue measurements. Model/validation checkpoint due.
10 · Brownian motion & stochastic dynamics
Ready		How does noise accumulate over time? Independent Brownian increments satisfy $\Delta W\sim N(0,\Delta t)$. Geometric Brownian motion solves $dS_t=\mu S_tdt+\sigma S_tdW_t$; its exact exponential solution includes the Itô correction.Check increment scaling and quadratic variation. Compare Euler–Maruyama with exact GBM using the same Brownian increments; refine nested grids and separate strong error, paired mean error, and Monte Carlo uncertainty. Stress positivity and audit a fitted daily log-growth proxy against bike observations.Module 10 notebook. Complete Lab 5 Part B and submit once with Module 9 Part A; combined Lab 5 due. Distinguish numerical error from model error and avoid treating a count proxy as a physical diffusion.
11 · Gaussian processes & prediction uncertainty
Ready		What does a smooth prediction leave uncertain? A Gaussian process has jointly Gaussian finite collections, mean $m(x)$, and a positive-semidefinite covariance kernel $k(x,x')$. Compare RBF and exponential kernels, and distinguish latent-function variance from observation variance.Use Cholesky solves for Gaussian conditioning; vary length scale and observation noise, check covariance matrices, and compare prior and conditional paths. Fit the bike-data mean and scale using January–August only; fix all September–December forecasts at August 31. Compare two prespecified RBF length scales with training-mean and last-training-value baselines, and audit interval coverage and extrapolation.Module 11 notebook. Begin Lab 6 Part A; Module 12 completes Part B, with one combined submission in week 12. State what each interval includes and treat the later period as reused development data, not a fresh test.
12 · Model comparison, validation & sensitivity
Ready		Which model improves the actual decision? Compare forecasts made with the same available information, horizon, and targets. Use MAE/RMSE, Gaussian negative log predictive density, a Brier score for a stated threshold, and interval coverage, width, and proper interval score.Use January–June as initial history, July–August to select between two rolling GP length scales, and September–December for reused assessment. Compare persistence and weekly-lag baselines on identical one-day targets; update only from earlier observations. Vary predictive SD, examine paired loss differences with a block-bootstrap sensitivity check, and expose target leakage.Module 12 notebook. Freeze the final evaluation protocol, state its limits, and report score uncertainty and influential assumptions. Complete Lab 6 Part B and submit once with Module 11 Part A; combined Lab 6 due. No additional project is added.
13 · Project refinement, reproducibility & AI verification
Ready		Can a colleague reproduce and explain the result? Separate a repeatable computation from evidence for a model. Check probability normalization, units, limiting cases, chronological information, and analytical benchmarks.Audit the same bike-sharing sample and refine a compact reproducibility record; rerun computations from a clean state, inspect seed behavior, and test flawed claims or code. Consequential AI assistance must be verified and explainable; the activity requires no AI account.Module 13 notebook. Six short concept labs

Each lab is a supplied notebook with two small experiments, two or three annotated plots/tables, and at most 250 words of interpretation. Expect 60–90 minutes outside class. Starter code handles data loading and routine plotting; advanced extensions are optional and ungraded. Paired discussion is welcome, but each student submits their own predictions and interpretation.

  1. Lab 1, week 2: independent versus persistent paths; estimate a two-state transition matrix and compare predictions.
  2. Lab 2, week 4: begin Part A with hitting-time simulation in Module 3; complete Part B with Monte Carlo error and one rare-event importance-sampling comparison in Module 4. Submit one combined lab in week 4. The guided variance-reduction demonstrations support the same lab and project; no additional assignment is added.
  3. Lab 3, week 6: begin Part A in Module 5 by diagnosing a supplied MCMC sampler against a conjugate benchmark. Part B in Module 6 propagates offspring-mean uncertainty from a synthetic offspring sample into branching outcomes and audits whether real data support the model. Submit one combined lab in week 6; no additional project is added.
  4. Lab 4, week 8: begin Part A in Module 7 with Poisson counts, integrated intensity, and a chronological bike-rate comparison. Part B in Module 8 compares renewal waiting times, stationary time occupation in a small birth–death chain, and the limits of daily observations. Submit one combined lab in week 8; no additional project is added.
  5. Lab 5, week 10: begin Part A in Module 9 with an event-simulation trace, one stable queueing benchmark, and a capacity comparison. Part B in Module 10 checks Brownian increment scaling and a coupled stochastic time-step approximation. Submit one combined lab in week 10; the separate project checkpoint remains due in week 9.
  6. Lab 6, week 12: begin Part A in Module 11 by comparing two GP settings with fixed-origin baselines and distinguishing latent from observation uncertainty. Module 12 completes Part B with rolling-origin model comparison, proper scores, and sensitivity to predictive uncertainty and dependent errors. Submit one combined lab in week 12; reuse the existing project where appropriate, with no additional project.

Each includes one brief AI-output verification task using a provided flawed statement or code fragment. No live AI service is needed. The lab rubric rewards correct modeling/computation (30%), verification (30%), interpretation/limitations (30%), and readable reproducibility (10%). Labs are equally weighted within their category.

Responsible AI-assisted work

AI may help with exploration, explanations, coding, and debugging; using it is optional. Every student must be able to explain, modify, and defend submitted work. Record consequential assistance, the output you adopted or rejected, and the mathematical or empirical check that supported your decision. “No AI assistance used” is a valid log entry.

AI inference demand is also a possible modeling domain. Arrival rates, service times, and capacity must come from documented measurements or be labeled scenario assumptions. A plausible generated number is not observed data, and a prediction comparison is not evidence of a causal effect.
