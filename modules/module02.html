Week 02 · Concept lab 1, part B

Does yesterday help
predict tomorrow?

Give the model a memory of the current state. Then check how far that memory helps.

This completes the two-week concept lab begun in Module 1. Guided work can happen in class; exercises fit within the normal notebook-practice budget. No additional project is assigned. Learning targets: define states, estimate a transition matrix, compute multistep probabilities, and compare forecasts without using future information.

01 / Practical questionTomorrow's flag, given today's flag.

In Module 1, high-demand days clustered more than independent Bernoulli trials predicted. We now ask a narrower question: does knowing today's high-demand indicator improve the probability forecast for tomorrow, next week, or 30 days ahead?

We keep the same 365 daily rental observations, the same January–August training period, and the same September–December evaluation period. That makes the comparison interpretable: the main change is the model's use of the current state.

Same observations, same limits

The source measures completed rentals, not latent demand or unmet requests. The threshold $c=4000$ rentals/day is a scenario assumption, not measured fleet capacity. September–December was inspected in Module 1: it is now a reused development holdout. A final project claim would need a new untouched future period.

02 / Concepts & mathematicsChoose a state. State what it remembers.

Let $X_t$ be observed daily rental counts and $Y_t=\mathbf1\{X_t>c\}$. Our state space is $S=\{0,1\}$: state 0 means “at most the threshold,” state 1 means “above the threshold.” The time step is one day. Counts exactly equal to $c$ belong to state 0.

A first-order Markov assumption says that, once we know today's state, older states add no information about tomorrow's distribution:

$$\mathbb P(Y_{t+1}=j\mid Y_t=i,Y_{t-1},\ldots,Y_0)=\mathbb P(Y_{t+1}=j\mid Y_t=i).$$

The equality is required for histories with positive probability. A time-homogeneous model further assumes that these transition probabilities do not depend on the calendar day. These are two separate assumptions. Weather, seasonality, and discarded count information can make either implausible.

$$P_{ij}=\mathbb P(Y_{t+1}=j\mid Y_t=i),\qquad P=\begin{pmatrix}1-a&a\\b&1-b\end{pmatrix}.$$

State order is always $(0,1)$. Rows are the current state; columns are the next state. Here $a=P_{01}$ and $b=P_{10}$, and both are probabilities per daily transition.

$$P_{ij}\ge0,\qquad \sum_jP_{ij}=1.$$

The matrix and an initial distribution together specify the chain. Using row distributions $\nu_t=(\mathbb P(Y_t=0),\mathbb P(Y_t=1))$, we update by $\nu_{t+1}=\nu_tP$. If today's state is known to be 1, $\nu_0=(0,1)$.

A state definition is a modeling choice

Reducing counts to a binary flag loses information. Even if a richer system were Markov, this thresholded process need not be Markov. Better one-day prediction provides evidence of usefulness, not a proof that all earlier history is irrelevant.

03 / Real-data preparationCount transitions before normalizing.

Preserve the order of the dates. From the $m=243$ training days, count only the $m-1=242$ adjacent pairs whose two dates are both in the training period:

$$N_{ij}=\sum_{t=1}^{m-1}\mathbf1\{Y_t=i,Y_{t+1}=j\},\qquad N_i=\sum_jN_{ij},\qquad \widehat P_{ij}=\frac{N_{ij}}{N_i}\quad(N_i>0).$$

These are conditional frequencies and, under the homogeneous Markov model, maximum-likelihood row estimates conditional on the starting state. Dividing every entry by 242 estimates frequencies of pairs, not conditional transition probabilities.

$$N=\begin{pmatrix}114&20\\19&89\end{pmatrix},\qquad \widehat P=\begin{pmatrix}114/134&20/134\\19/108&89/108\end{pmatrix}\approx\begin{pmatrix}0.8507&0.1493\\0.1759&0.8241\end{pmatrix}.$$

Interpret $\widehat P_{01}$: among 134 training pairs starting with a state-0 day, 20 move to state 1. The 109 high-demand training days yield only 108 departures from state 1, because the final training day—August 31—is high but its following day is outside training.

states = (train["cnt"].to_numpy() > 4000).astype(int)
counts = np.zeros((2, 2), dtype=int)
np.add.at(counts, (states[:-1], states[1:]), 1)
support = counts.sum(axis=1)
if np.any(support == 0):
    raise ValueError("An origin state has no observed transitions")
P_hat = counts / support[:, None]

Boundary rule: August 31 → September 1 is excluded from fitting. August 31's observed state can still initialize the forecast for September 1, because it is already known.

What if a row has no observed departures?

When $N_i=0$, the empirical conditional row is undefined. Do not silently fill it with zeros or call a uniform row an observed estimate. One explicit sensitivity choice adds a symmetric pseudocount $\eta>0$:

$$\widehat P_{ij}^{(\eta)}=\frac{N_{ij}+\eta}{N_i+2\eta}.$$

This supplies information through an assumption. With an unseen state, $\eta=0.5$ gives a row $(0.5,0.5)$ despite no observed departures. Check whether that assumption changes the decision. The main analysis uses $\eta=0$.

04 / Worked computationSum over paths with matrix multiplication.

Two daily transitions can pass through either intermediate state. For a homogeneous Markov chain,

$$\mathbb P(Y_{t+2}=j\mid Y_t=i)=\sum_{k\in\{0,1\}}P_{ik}P_{kj}=(P^2)_{ij}.$$

More generally,

$$\nu_h=\nu_0P^h,\qquad P^0=I,\qquad (P^{r+s})_{ij}=\sum_k(P^r)_{ik}(P^s)_{kj}.$$

For the synthetic worked example $P=\begin{pmatrix}0.8&0.2\\0.3&0.7\end{pmatrix}$, starting at state 1, the two-day probability of state 1 is

$$ (P^2)_{11}=P_{10}P_{01}+P_{11}P_{11}=0.3(0.2)+0.7(0.7)=0.55.$$

The two paths are $1\to0\to1$ and $1\to1\to1$. Squaring each entry separately would keep only one part of this calculation and generally destroy row normalization.

P = np.array([[0.8, 0.2], [0.3, 0.7]])
nu0 = np.array([0.0, 1.0])
h = 7
nu_h = nu0 @ np.linalg.matrix_power(P, h)
print(nu_h)  # probabilities in state order [0, 1]

Define the event precisely: $(P^h)_{i1}$ is the probability of being high on day $h$, not the probability of at least one high day during the next $h$ days. Multistep forecasts do not insert the realized intermediate future states.

For $R$ independent paths with the same known initial state, endpoint indicators are independent across paths even though consecutive states within a path may be dependent. If $q_h=(P^h)_{i1}$,

$$\operatorname{MCSE}(\widehat q_h)=\sqrt{\frac{q_h(1-q_h)}{R}}.$$

This is simulation error conditional on a fixed matrix, not uncertainty in the fitted matrix or evidence that the model is correct. Browser Mulberry32 and NumPy use different random streams; seed 6231 reproduces each implementation separately.

06 / Real-data applicationFreeze the fit. Advance the forecast origin.

Fit $\widehat P$ using January–August. At each later forecast origin $t$, observe $Y_t$, then predict $Y_{t+h}$ using $(\widehat P^h)_{Y_t,1}$. The matrix stays fixed. For a seven-day forecast, the observed states on the intervening six days are not inputs to that forecast.

Origins begin on August 31, the day the training period ends. That gives 122 one-day forecasts (targets September 1–December 31), 116 seven-day forecasts (targets September 7–December 31), and 93 thirty-day forecasts (targets September 30–December 31). All fitting information is available by every origin.

07 / Validation & interpretationA useful short-term model can be a weak long-term forecast.

For identical origin–target pairs, compare three probability forecasts: the fitted Markov probability, the constant iid estimate $\widehat p=109/243$, and persistence (probability equal to the observed current state, either 0 or 1). The Brier score is

$$\operatorname{BS}_h=\frac{1}{M_h}\sum_{t\in\mathcal O_h}\left(q_{t,h}-Y_{t+h}\right)^2,$$

where $\mathcal O_h$ is the set of valid forecast origins and $M_h$ its size.

At the default threshold, the one-day scores are about 0.1749 (Markov), 0.2417 (iid), and 0.2213 (persistence). At 30 days, the Markov score is about 0.2354, versus 0.2322 for iid. Compare methods within each horizon row: different horizons use different target dates, so cross-row changes do not isolate the effect of horizon alone.

Verify the mathematics and code

Check row sums and nonnegativity; verify $P^0=I$, $P^1=P$, and a hand-computed entry of $P^2$. Compare simulated endpoints with matrix powers. Identity and alternating matrices expose indexing errors.

Validate the assumptions against data

Check later scores and calibration by origin state. Compare within-test transition frequencies descriptively without refitting. A change in a row may reflect seasonality, sampling variability, or omitted state information.

The notebook includes row support and calibration checks. Transition pairs overlap; forecast errors also share dates and histories. Do not treat 122 dependent forecasts as independent trials to attach a naive standard error to a score difference.

Uncertainty: path variability remains even with a known matrix; finite row counts make the fitted entries uncertain; seasonality and imperfect state definitions create model uncertainty. More simulated paths reduce Monte Carlo error only. A smoothing choice is a sensitivity analysis, not a calibrated uncertainty interval.

These scores support a predictive comparison on one reused period. They do not estimate the causal benefit of adding bikes or staff, and do not establish that the thresholded rental process is truly Markov.

08 / AI verificationCorrect-looking matrix code can answer the wrong question.

This is an instructor-written flawed assistant-style proposal, not output attributed to an AI service. No account is needed to audit it:

# Claim: row-vector h-step forecast, using only information at the origin
P_candidate = fit_transition(transition_counts(y_all))
nu0 = np.array([0.0, 1.0])
nu7 = nu0 @ (P_candidate ** 7).T

Check three separate claims: what data were used to fit the matrix, whether ** h means matrix power for a NumPy array, and whether the transpose matches the stated row-vector convention. A row-sum test is useful but cannot detect every mistake; symmetric or special matrices can conceal orientation errors. Use an asymmetric matrix with a known two-step result.

Record consequential assistance, the mathematical and empirical checks you performed, and your changes. “No AI used” is valid. Be ready to explain the conditional probability represented by every matrix entry and forecast.
