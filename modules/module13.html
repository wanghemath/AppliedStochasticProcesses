01 / Practical questionWould the conclusion survive a clean start?

A notebook can print the same answer twice because it repeats a mistake. It can also compute a probability correctly for a model that does not describe the observed system. Your final project needs a reproducible computation, verified implementation, and an appropriately limited scientific claim.

02 / Record the recipeThe seed is one input, not the whole experiment.

Think of the output as a function of the complete experiment:

$$R=F(D,\theta,U;C,E).$$

Here D is the data, θ the declared configuration, U the pseudo-random stream, C the code, and E the software environment. A seed helps reconstruct U only with its generator, call order, and implementation. Changing any other argument can change R even when the seed is unchanged.

A hash establishes identity under the chosen representation; it does not prove accuracy, authenticity, permission to redistribute, or a correct interpretation. Record the serialization convention. The provided tested dependency snapshot pins direct packages; it is not a complete cross-platform environment lock.

Clean-start protocol: save the notebook, restart the kernel, run all cells in order, inspect outputs and assertions, then save the executed artifact. Run from the documented directory and confirm paths resolve without personal absolute paths. Repeat the same configuration, change only the seed, and identify which outputs should remain invariant. A manifest's presence alone is not evidence that someone performed these steps.

03 / Check the mathematicsUse a second route to the answer.

Let St be a binary state and let rows of P describe the current state and columns the next state. Write a=P01 and b=P10:

$$P=\begin{pmatrix}1-a&a\\b&1-b\end{pmatrix},\quad 0\leq a,b\leq1,\qquad \mu_h=\mu_0P^h.$$

A valid transition matrix has finite nonnegative entries and row sums one. That structural check is necessary, but an incorrectly fitted or transposed calculation can still pass it. Challenge the result using independent reasoning.

If ph is the probability of state 1 after h transitions, starting from a known state s, then

$$p_{h+1}=a+(1-a-b)p_h,\quad p_0=s;\qquad p_h=\frac{a}{a+b}+\left(s-\frac{a}{a+b}\right)(1-a-b)^h\quad(a+b>0).$$

The recurrence follows by conditioning on the previous state. Its closed form is independent of a matrix-power implementation. When a+b=0, the chain is the identity and ph=s. At h=0, every method must recover the initial state. When a=b=1, states alternate: a stationary distribution exists, but the distribution from a known state does not converge to it.

A hand-computable fixture

For $P=\begin{pmatrix}.8&.2\\.3&.7\end{pmatrix}$, starting in state 0, the probability of state 1 after two transitions is $.8\times.2+.2\times.7=.30$. A plausible-looking program that gives .45 has likely confused the starting row with the destination column.

Additional checks should fail when the relevant mistake is introduced: invalid probabilities; missing transition-row support; current-target leakage; a mismatched date; a wrong unit conversion; or a reseeded random stream. Re-running the same implementation or asking a second AI for agreement is not an independent mathematical check.

The threshold is a declared scenario definition, not measured system capacity. 05 / Replay and break itRepeatability does not create independent replications.

Simulate N independent paths conditional on a fixed P. Let $I_r=\mathbf1\{S_h^{(r)}=1\}$. The terminal probability estimate and conditional Monte Carlo standard error are

$$\widehat p=\frac1N\sum_{r=1}^NI_r,\qquad \widehat{\mathrm{MCSE}}=\sqrt{\frac{\widehat p(1-\widehat p)}{N}},\qquad \mathrm{SE}=\sqrt{\frac{p_h(1-p_h)}{N}}\leq\frac1{2\sqrt N}.$$

The last formula uses the exact model probability and independent paths. The bound concerns standard error, not the realized absolute error. A zero plug-in MCSE can occur after identical endpoints even in a small valid experiment; it does not prove the probability is known. Parameter uncertainty and model misspecification are outside these conditional formulas.

Predict: multiply N by 100. How should the MCSE scale? Then reset the same seed inside every path: would increasing N supply any new randomness?

Same seed, code, call order, and compatible environment reproduce a run. A larger N reduces the standard error, but a particular realized error need not decrease monotonically. A changed seed explores Monte Carlo variability; it should not change the fitted matrix, exact probability, or deterministic validation score. The browser initializes its generator once per run in the correct mode. Parallel work needs deliberately managed streams; copying one seed to every worker is not a general independence strategy.

With some balanced count matrices, the wrong axis can accidentally produce valid row sums; inspect the actual origin counts and row denominators too. The hand fixture and a separate closed form check the computation. None establishes that bike states are homogeneous Markov observations.

For each September–December target t, use the frozen January–August matrix and the previous observed state: $q_t=\widehat P_{S_{t-1},1}$. Persistence gives probability $S_{t-1}$. Both predict the same 122 targets, including September 1 from August 31. Earlier assessment states may update the next origin's input, but never the fitted matrix. This is rolling one-day prediction, not a four-month forecast issued at one origin.

Simulation precision can be excellent while the operational claim is unsupported. In your project, identify a decision variable that is actually measured or controllable, and state what evidence would justify moving from a scenario to a recommendation.

Keep four uncertainties separate: conditional Monte Carlo error; uncertainty in estimated transition probabilities; structural uncertainty about the homogeneous Markov assumption; and uncertainty in scenario inputs. 07 / Audit AI outputTest the claim, not the confidence of its wording.

The following is a deliberately flawed, instructor-written AI-style proposal. No account or live AI tool is required. Treat the claims as hypotheses to inspect.

states = (all_counts >= 4000).astype(int)
counts = transition_counts(states)  # includes future assessment dates
P = counts / counts.sum(axis=0)     # claimed current-state rows
for r in range(N):
    rng = np.random.default_rng(seed)
    terminal[r] = simulate_one_path(P, rng)
mcse = np.sqrt(terminal.mean() * (1-terminal.mean()) / N)
# "Same seed and tiny MCSE verify N independent replications."
# "The 4000 threshold measures bike capacity; this intervention prevents shortages."

Identify the exact data dependency, normalization axis, and random-stream scope. Check the equation behind the uncertainty claim and the measurement behind the capacity claim. Keep a record of the expected failure, the correction, and independent evidence for the corrected result. Agreement with a second generated answer is not enough.

Complete the matching notebook investigations as a refinement of the sustained project. There is no seventh concept lab, new project, or extra submission. Keep the week-14 deliverables aligned: executed notebook, 4–5 page report, one-page decision brief, and presentation.

  3. E3 — Refine the model without overstating the evidence. Compare the frozen chain and deterministic persistence on the same 122 September–December one-day state targets using Brier loss. Change a future count enough to flip its state and identify which forecasts can change. Compare factors 0.5, 1, and 1.5 on the low-to-high transition probability, holding the high-to-low probability fixed; distinguish conditional Monte Carlo error, fitted-parameter uncertainty, structural uncertainty, and an unmeasured scenario from a causal intervention.
